## 1. Business Context & Objective

### High Level Overview: From Manual Settlement Decisions to AI-Driven Optimized

#### Business Challenge

**Objective:**
A conversational AI agent that gives collections analysts, portfolio managers, and senior stakeholders instant, model-grounded answers about the settlement portfolio, replacing ad-hoc notebook runs with a natural-language interface backed by the live modelling infrastructure.

**Current Challenges:**
- Manual settlement decisions (Excel / notebooks)
- Inconsistent settlement offers
- No unified view of portfolio value
- Difficult scenario analysis
- Limited scalability

**Result:**
- Suboptimal recovery
- Slow decision-making
- Lack of transparency

#### Solution Overview

**Objective:**
Use of a three-stage probability chain in combination with EV (Expected Value) & MILP (Mixed-Integer Linear Programming) to create an AI-driven decision system.

**AI-powered decision system that:**
- Optimizes settlement offers
- Maximizes portfolio Expected Value (EV)
- Provides explainable recommendations
- Enables scenario analysis in real time

**Result:**
From data → decisions → explanations

## 2. Solution Architecture

### AI-Driven Decision System Pipeline

**System Overview (6 Stages):**

1. **Borrower Data Collection**
   - Customer Profile
   - Payment History
   - Transaction History
   - Financial Indicators
   - Behavioral Attributes

2. **Predictive Models** — Three-stage probability chain:
   - **PoAPP:** Contact → Application
   - **PoA:** Application → Acceptance
   - **PoF:** Acceptance → Fulfillment
   - **Combined Outcome:** Probability of successful recovery

3. **Expected Value Logic**
   - **EV Formula:** `EV = PoAPP × PoA × PoF × Settlement Amount`
   - **Key insight:** The system doesn't just optimize recovery rate — it optimizes expected value.

4. **Optimization Engine (MILP)**
   - **What the optimizer does:**
     - Tests all possible offer combinations (grid)
     - Varies recovery rates and instalments
     - Selects the best global portfolio outcome
   - **Constraints:**
     - Budget Limits
     - Business Rules
     - Capacity Constraints
     - Time Constraints

5. **Offer Grid** — Offer Generation Engine:
   - Instalment Plan Proposals
   - Discount Scenarios
   - Alternative Settlement Options
   - Expected Value per Offer

6. **AI Agent Interface** — Business Decision Support Platform:
   - Scenario Simulation
   - Explainable Recommendations
   - Decision Support
   - Business Insights
   - **Agent Capabilities — 3 Core Domains:**
     - Portfolio Monitoring
     - Settlement Optimization
     - Economic Terms Analysis

**Business Value:**
- ↑ Recovery Rate
- ↓ Decision Time
- ↑ Consistency
- ↑ Transparency
- ↑ Scalability

> **Note:** The LLM does not make business decisions. It explains and communicates the optimized outputs generated by the decision engine.

### Architecture Design

The diagram illustrates an **LLM-orchestrated decisioning and analytics platform** for portfolio optimization, borrower assessment, monitoring, and explainability. The architecture is organized into four logical layers: **user interface**, **orchestration layer**, **analytical tools**, and **data/model assets**.

**High-Level Description:**
The platform integrates six core services covering borrower lookup, offer optimization, portfolio monitoring, efficient frontier analysis, predictive model scoring, and model explainability. These services access a shared data and model ecosystem that includes application and payment datasets, pre-scored offer grids, monitoring baselines, predictive model bundles, and a vector-based knowledge store.

By separating the user interface, orchestration layer, analytical tools, and data/model assets, the architecture delivers a scalable, modular, and explainable solution for decision support. The result is a conversational analytics environment where complex optimization, monitoring, and risk assessment tasks can be executed and explained through a single natural-language interface.

### Indicative AI Orchestration Layer (Enterprise AI Platform)

> **Note:** The Enterprise AI Platform functions as an intermediate layer (AI Orchestration Layer) between the client and the organization's information systems.

#### Communication Channels
Web Chat · Mobile App · WhatsApp · Viber · Voice / IVR · Email · SMS

#### Step-by-Step Communication Flow

1. Customer sends a message from any channel (web chat, mobile app, WhatsApp, email, etc.).
2. The message passes through the API Gateway securely (HTTPS/WebSocket).
3. The user is authenticated via IAM (SSO / MFA / RBAC) and a secure session is established.
4. The AI Agent Service determines intent, manages the conversation, and decides which tool/service to call.
5. If information is needed from documents/policies, the RAG Engine searches relevant documents via the Vector Database and returns results to the LLM.
6. The LLM (Gemini), based on data from tools and retrieved documents, analyzes the request and formulates a response.
7. The Tool Orchestrator executes the appropriate tool (e.g., balance check, restructuring simulation) via the Integration Layer.
8. The Integration Layer connects to backend systems (CRM, Debt Management, Payments, etc.) and retrieves real-time data.
9. The Rule Engine applies business rules (e.g., maximum amounts, data policies), and the Workflow Engine manages approvals and escalations.
10. The response is returned to the customer via the original channel, in real time.

## 3. Operating Model & Conversational Design

### Questions to Answer for the End-to-End Operating Model

1. **Decision Ownership** — Define what the AI, Rule Engine, Manager and Executive each decide.
2. **Exception Handling** — Fallback flows, degraded mode, retry/compensation, conflict resolution.
3. **Data Quality & Completeness** — Handling of missing data, mandatory vs optional fields, validation rules.
4. **Policy Lifecycle** — Business rules evolve — versioning, ownership and controlled updates.
5. **Compliance & Auditability** — Why / who approved / which policy version. Traceability & immutable logs.
6. **Latency & Performance** — Max response per intent, sync vs async, caching, timeout fallback.
7. **Human Workload (HITL)** — Queue prioritization, batching, auto-approval thresholds, balancing.
8. **Risk Stratification** — Low/med/high routing, dynamic thresholds, behavioral scoring.
9. **Feedback Loop** — Learn from overrides, rejected suggestions, outcomes, customer behavior.
10. **Failure Modes** — LLM hallucination, rule vs workflow conflict, integration downtime.
11. **Organizational Alignment** — Who owns rules, workflows, data and AI behavior.

### Customer Questions vs Required Inputs

**Key message:** Intent → Required Data → Tool calls → Rule Engine → Response

| # | Intent | What the Customer Asks | Required Data |
|---|---|---|---|
| 1 | Debt restructuring / installment plan | "Can I restructure my debt?" · "How many installments can I pay in?" · "How much will I pay per month?" | Customer ID / Tax ID (AFM); current debt (auto from system); overdue status (days overdue); desired # of installments (optional); monthly payment capacity (optional); consent (acknowledgement) |
| 2 | Debt inquiry | "What is my balance?" · "What outstanding obligations do I have?" | Customer ID / login; (optional) contract selection if multiple exist |
| 3 | Payment history | "What have I paid so far?" · "Which installments have been covered?" | Customer ID; time range (optional: last 6 months / all time) |
| 4 | Decision explanation | "Why was it not approved?" · "What can I do to get it approved?" | Request ID / case ID; customer ID (auto); context from rule engine + workflow |
| 5 | Re-negotiation | "Can you give me more installments?" · "Can I reduce the installment amount?" | Existing plan ID; current installment plan; financial constraints (optional); income range (optional / self-declared) |
| 6 | Policy / exception request | "Can I get an extension?" · "Is there a grace period?" | Customer ID; contract ID; reason for request (free text) |
| 7 | Guidance / recommendation | "What can I do about my debt?" · "What are my options?" | Request ID / case ID; customer ID (auto); context from rule engine + workflow |
| 8 | Human handoff | "Can I speak to a representative?" | Reason for escalation; conversation ID; customer verification status |

## 4. Governance & Human-in-the-Loop

### Human-in-the-Loop: Key System Questions

**Key message:** Proposed Action + Rules + Risk + Alternatives + Approval Path + Explanation

| # | Question | Layer | The System Must Answer |
|---|---|---|---|
| 1 | "What does the system recommend and why?" | Explainability layer | What decision is being recommended? Which rule was used? What data was used? Which policy supports it? |
| 2 | "Is this within allowed limits?" | Rule validation | Is any business rule violated? Is there an exception? Is this a borderline case? |
| 3 | "Does this require human approval?" | Approval routing | Is any business rule violated? Does it exceed thresholds? Is the customer high-risk? Is it a manual-only case? |
| 4 | "Who should approve it?" | Workflow routing | Supervisor / agent / risk team; region/department-based routing; role-based assignment |
| 5 | "What alternative options exist?" | Decision alternatives | Stricter arrangement; more flexible arrangement; reject / defer / renegotiate |
| 6 | "What happens if it is approved or rejected?" | Outcome simulation | What decision is recommended? What changes in the system? What is the impact on the customer? What workflow is triggered? |
| 7 | "How risky is this decision?" | Risk scoring | What decision is recommended? Credit risk; payment probability; historical behavior |
| 8 | "What data is missing for a safe decision?" | Data completeness check | Missing income information; missing contract details; missing identity verification |
| 9 | "Is it compliant with policy / regulation?" | Compliance layer | Legal constraints; internal policies; regulatory rules |
| 10 | "What explanation will the customer see?" | Customer-facing explanation | How will the LLM explain it? Is it simple and understandable? Is it defensible? |
